# 199 页 3D 演示分镜表

> 这是“所有算法 3D 演示升级”的规划文档，不是代码实现。目标是把 199 个页面从“同一机位的平面动画”升级为“有镜头、有标注、有状态面板、可交互”的 3D 演示。

## 现状判断（为什么这样规划）

- **199/199 页共用同一组 `cameraPos/lookAt`**，脚本中没有镜头运动；主体经常只占舞台 20%–40%。
- **0 页有自定义输入**；191 页只有“演示/清空”，只有少数排序页有随机化/变体按钮。
- `3D/modes` 下 6 个通用原型中 **5 个 0 页使用**，`Geometry3D` 仅 5 页使用；其余页面大量手写，风格和布局不一致。
- 叙事主要靠底部状态栏；右侧说明栏是静态的，**0 页随步骤更新**；0 图例、0 键盘快捷键、0 `prefers-reduced-motion`。
- 截图中的典型问题：AVL 首帧只有顶部一个球、AES 只有 16 个“00”、FCFS 标签换行压住色块、FFT 只有灰盒子、KMP 的指针没有标签且播放中状态仍是“就绪”。
- 结论：不是继续加粒子，而是补 **镜头导演 + 场景标注 + 实时状态面板 + 算法专属心智模型 + 可交互/可回退**。

## 怎么读

每页一行，字段如下：

| 字段 | 含义 |
|---|---|
| 页面 | 链接到原页面；下方是当前演示脚本，便于实现时定位 |
| 原型 | 复用的演示原型代码，见下方“原型代码” |
| 算法逻辑 | 该页的算法说明总述，来自 `3D/autodemo.js` 的 `ALGO_DESC` |
| 舞台 / 心智模型 | 这一页的物理隐喻和场景 |
| 镜头 | 建立 → 动作 → 结果 的机位语言 |
| 分镜节拍 | 按算法子步骤展开的动作序列；实现时每个“→”是一个节拍 |
| 常驻状态 | 右侧/底部状态面板应实时显示的量 |
| 交互 | 输入、操作、预测、对比等玩法 |
| 名场面 | 这一页最值得记住的一个镜头 |
| 优先级 | P0 第一波标杆、P1 第二波、P2 模板化补齐 |

P0 行的舞台/镜头/状态/交互/名场面已按 `07` 终稿更新；实现 P0 时以 `07a/07b` 的逐拍表为准。

## 优先级与实施波次

| 优先级 | 含义 | 建议 |
|---|---|---|
| P0 | 第一波标杆，覆盖主要舞台类型 | 先做 20–26 页，验证框架和设计语言 |
| P1 | 第二波，主流程和常用算法 | 复用 P0 模板，按类批量迁移 |
| P2 | 第三波，长尾与简单页 | 模板化补齐，重点保证清晰和一致 |

建议波次：

1. **Wave 1（P0）**：BFS、DFS、Dijkstra、A*、Bellman-Ford、Prim、Kruskal、ComparisonSort、HeapSort、RadixSort、BST、AVL、红黑树、B+ 树、Trie、Knapsack、LCS、LIS、编辑距离、KMP、AES、RSA、CNN、Transformer、Raft、Grover。
2. **Wave 2（P1 第一批）**：其余图算法、树/哈希、DP、OS 调度/页面/磁盘、字符串核心、密码核心。
3. **Wave 3（P1 第二批）**：ML/分布式其余页面、数学数值、压缩/编码、堆结构、几何。
4. **Wave 4（P2）**：长尾页面、简单页、模板化补齐。

## 全站统一系统

### 舞台
- 深空观测台：星空背景 → 雾化地面网格 → 发光舞台 → 主体 → 标注 → HUD，六层景深。
- 主体占画面 55%–75%；空场景用“待插入槽位/预告轮廓”填满，避免一个球孤零零挂在上面。

### 镜头
- 每页 3–5 个镜头位：Establish（建立）→ Focus（跟随动作）→ Detail（看不变量）→ Payoff（看结果）→ Recap（口诀）。
- 过渡 600–900ms，缓入缓出，可被用户拖拽打断；用户拖拽后 5 秒内不抢镜头，提供“回正”。
- 移动端自动 `fitBounds`，竖屏降低机位，不沿用桌面机位。

### 色彩语义（全站固定）
| 语义 | 颜色 | 冗余编码 |
|---|---|---|
| 当前/处理中 | 青 | 外环 + 呼吸 |
| 候选/边界 | 金 | 虚线环 + 小旗 |
| 确认/完成 | 绿 | 实心 + 对勾 |
| 冲突/错误 | 红 | 抖动 + 叉号 |
| 已访问/历史 | 蓝灰 | 降低亮度 |
| 未访问/空闲 | 深灰 | 无发光 |

页面主题色只做“身份色/背景点缀”，不覆盖状态语义。

### 标注
- DOM 覆盖层 + 3D 锚点投影 + 引导线；场景内只放短标签（≤12 字），长解释进 HUD。
- 同一时刻最多 6–8 个标注；碰撞避让，避免文字压盖。

### HUD
- 左上：章节名/算法变体；左下：当前动作 + 为什么 + 状态增量；右侧：说明/状态/复杂度三个页签；底部：章节时间轴 + 播放/单步/回退/重播/速度/镜头/专注。
- 状态页实时显示队列、栈、PQ、DP 表、dist、日志等；复杂度页显示当前操作与总复杂度。

### 运动语法
比较 = 光束；交换 = 弧线 + 火花；访问 = 波纹；确认 = 落定；失败 = 抖动 + 红环；合并 = 汇流；分裂 = 让位。一个节拍最多 2 个焦点物体。

### 五幕结构
Hook（3–5s）→ Model（5–10s）→ Core loop（20–60s）→ Invariant（5–10s）→ Payoff/Takeaway（5–8s）；每页可暂停细读。

### 交互与学习玩法
自定义输入、预设/边界用例、单步/回退/时间轴、预测下一步、双算法对比、电影/学习双模式、分享状态、结课小测、可选音效（默认关闭）。

### 性能与可访问性
- 桌面 60fps、移动端 ≥30fps；输入响应 <50ms；实例化、对象池、文字纹理缓存、离屏暂停、DPR 上限、特效预算。
- 键盘快捷键、`aria-live`、减少动态、色盲安全、移动端 44px 触控；长文本用 DOM，不用 3D 精灵。

## 使用建议

1. 先读 `07-p0-review.md`，按 A–E 顺序实施；`06-tier1-detailed.md` 只是 6 页快速样例，P0 终稿在 `07a/07b`。
2. 在 `3D/director/` 下落 CameraDirector / AnnotationLayer / BeatHUD / StateInspector / InputKit；`3D/modes` 现代化后复用。
3. 每页实现时，把本表的“分镜节拍”展开成逐拍表：节拍 | 画面 | 镜头 | 标注 | 状态 | 交互。不要直接把整段文字塞进 3D。
4. 每页验收：首屏 3 秒能看懂“看什么”；每拍一个动词；状态面板能读出当前状态；至少 1 个交互；手机不裁切；无标注重叠。
5. 199 页全量重做的工作量约 120–200 人日；2 名开发 + 1 名设计约 4–5 个月。只做 20–26 页 P0 约 8–10 周（1 人）/ 6–7 周（2 人）。
