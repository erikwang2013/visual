# 算法演示动画叙事重构 —— 试点设计（2026-08-14）

## 背景与目标

项目含约 199 个算法 3D 演示页面，批次 1-7 已完成布局统一（相机/视口/坐标约定统一，全部页面通过视口验证）。本次目标：**按算法定义重新研究并重构每页的动画叙事**（步骤划分、阶段过渡、动效节奏、旁白同步），而非视觉风格升级。

范围先做试点：5 页完整跑通「研究→设计→设计检查→布局检查→3D动画设计→编码→代码审查→测试→交付确认」流水线，确认方向后按类别分批批量执行。

## 试点范围

| 页 | 渲染模式 | 代表性 |
|---|---|---|
| BFS | Graph3D | 图遍历，最基础 |
| Huffman | Tree3D | 树构建/贪心 |
| KNN | 自定义散点 | 散点/距离 |
| Raft | 自定义网格 | 分布式共识 |
| Strassen | 矩阵 | 数学分治 |

## 每页 8 环节流水线（单页串行，代理经 SendMessage 交接）

| 环节 | 代理 | 产出/交付 |
|---|---|---|
| ① 研究 | researcher | 算法步骤规范：输入示例、阶段→子步骤划分、每步可视化要点、复杂度、易错点 |
| ② 设计 | designer | 分镜设计：舞台分区、阶段列表、每阶段动效序列（进入/强调/转换）、旁白文案、节奏表 |
| ③ 设计检查 | design-checker | 对照算法定义核对叙事正确性（步骤顺序/示例数据/公式/结果）→ 通过或退回 |
| ④ 布局检查 | layout-checker | 对照布局标准核对所有对象坐标（smoke 脚本自动化） |
| ⑤ 编码 | coder | 在现有页面实现新叙事（生成器/文本/动效），不破坏布局标准 |
| ⑥ 代码审查 | reviewer | 代码质量 + 叙事与设计稿一致性 |
| ⑦ 测试 | tester | 浏览器播放：布局回归 + 分阶段文本/对象断言 + 控制台零错误 |
| ⑧ 交付确认 | 用户 | 浏览器播放 → 反馈 → 返修循环，确认后进入下一页 |

每页交接物在代理消息间传递，不落盘。

## 叙事重构标准

- **三幕结构**：概览（问题+目标）→ 逐步演示（按算法定义分阶段）→ 收尾（复杂度+应用+变体）
- **阶段粒度**：每页 3-6 个阶段；循环子步骤单次 300-500ms，关键阶段 ≥800ms；总时长 15-40s
- **动效语言**：沿用现有 `W/S/A` 生成器语法 + 高亮/连线/缩放强调关键对象
- **文案同步**：hint 顶部引导（阶段意图）、stageT 阶段名、eqT 公式/要点，与步骤严格同步
- **布局标准不变**：相机 `[320,500,900]` / lookAt `[320,500,0]` / fov 52；hint `x:700,y:560,scale:0.7,wrapChars:7`；可见 y∈[61,939]、x∈[0,640]；outT y=70

## 检查判据

- **设计检查**：步骤顺序与算法定义一致；示例数据正确（BFS 图结构、KNN 投票结果、Raft 选举轮次、Huffman 合并权重、Strassen 7 次乘法）；演示结果正确
- **布局检查**：NDC ±1.05 阈值内、标注不遮挡、无视口外对象（复用 smoke_verify.js）

## 测试

- 布局回归：smoke_verify.js
- 叙事核对：驱动播放+快进，断言各阶段文本按序出现、对象显隐正确
- 控制台零 error

## 试点顺序

BFS → Huffman → KNN → Raft → Strassen，每页走完整流水线并交付确认，确认后再开始下一页。

## 试点后批量策略

5 页全部确认后，按 index 分类分批（每批 8-15 页）跑同一流水线，**免逐页人工验收**，改为批次抽样验收 + 批次级自动化验证，逐批提交 git。试点页同时成为后续页的叙事模板。

## 不做的事

- 不升级视觉风格（材质/光效/配色）
- 不改布局标准（批次 1-7 成果）
- 不落盘每页设计文档
- 不并行执行多页流水线（保持单页串行，成本可预测、方向可纠偏）
